# Starlight Internationalization (i18n)

Starlight has built-in support for multi-language documentation sites, including routing,
fallback content, and full UI translation.

## When to Use i18n

Use Starlight's i18n when your docs need to be available in multiple languages. If you only
need a single language (even if it's not English), you can set the `defaultLocale` without
configuring full i18n — this sets the `lang` attribute and date formatting.

## Configuration

### Single non-English language (no i18n routing)

```javascript
starlight({
  title: 'Mi Documentación',
  defaultLocale: 'es',       // Sets lang="es" and locale formatting
  locales: {
    root: { label: 'Español', lang: 'es' },
  },
})
```

### Multi-language site

```javascript
starlight({
  title: {
    en: 'My Docs',
    es: 'Mi Documentación',
    ja: 'ドキュメント',
  },
  defaultLocale: 'en',
  locales: {
    // English at the root (no /en/ prefix)
    root: {
      label: 'English',
      lang: 'en',
    },
    es: {
      label: 'Español',
    },
    ja: {
      label: '日本語',
    },
  },
})
```

### How routing works

With the config above:
- `/getting-started/` → English (root locale)
- `/es/getting-started/` → Spanish
- `/ja/getting-started/` → Japanese

If a translated page doesn't exist, Starlight falls back to the default locale's content.

## File Structure

```
src/content/docs/
├── index.mdx              # English home (root locale)
├── getting-started.md     # English
├── es/
│   ├── index.mdx          # Spanish home
│   └── getting-started.md # Spanish translation
└── ja/
    ├── index.mdx          # Japanese home
    └── getting-started.md # Japanese translation
```

## Translating UI Strings

Starlight's UI (navigation labels, search placeholder, "On this page", etc.) ships with
translations for many languages. To customize or add missing translations:

### Content collection setup

```typescript
// src/content.config.ts
import { defineCollection } from 'astro:content';
import { docsLoader, i18nLoader } from '@astrojs/starlight/loaders';
import { docsSchema, i18nSchema } from '@astrojs/starlight/schema';

export const collections = {
  docs: defineCollection({ loader: docsLoader(), schema: docsSchema() }),
  i18n: defineCollection({ loader: i18nLoader(), schema: i18nSchema() }),
};
```

### Translation files

Create JSON files for each locale:

```json
// src/content/i18n/es.json
{
  "search.label": "Buscar",
  "tableOfContents.onThisPage": "En esta página",
  "page.editLink": "Editar esta página",
  "404.text": "Página no encontrada."
}
```

Expressive Code and Pagefind strings are also overridable in the same file using `expressiveCode.*`
and `pagefind.*` keys (e.g., `"pagefind.clear_search"`, `"pagefind.load_more"`,
`"expressiveCode.terminalWindowFallbackTitle"`).

## Sidebar Labels per Locale

Use the `translations` property on sidebar items:

```javascript
starlight({
  sidebar: [
    {
      label: 'Guides',
      translations: {
        es: 'Guías',
        ja: 'ガイド',
      },
      autogenerate: { directory: 'guides' },
    },
  ],
})
```

## RTL Support

Starlight automatically applies RTL layout for right-to-left languages (Arabic, Hebrew, etc.)
when the locale's `dir` is set:

```javascript
locales: {
  ar: {
    label: 'العربية',
    dir: 'rtl',
  },
},
```

## Translation Workflow Tips

- Start with your default locale content, then translate
- Use the same file paths across locales — Starlight uses path matching for fallbacks
- Untranslated pages show the default locale content with a notice
- Consider using a translation management tool or CI checks to track missing translations
- The sidebar order and structure is shared across all locales
